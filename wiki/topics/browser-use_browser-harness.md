# Browser Harness

## Summary [coverage: low — 1 source]

Scraped 2026-07-02T02:24:07Z. Browser Harness is a thin, self-healing CDP harness that connects an LLM directly to a real browser via a single WebSocket to Chrome, with nothing in between. It enables LLMs to complete arbitrary browser tasks by writing missing helper code at runtime — the harness improves itself each run as the agent discovers and files new domain skills. It targets use cases requiring complete freedom over browser automation, from local Chrome sessions to cloud-hosted stealth browsers.

## Core Pattern [coverage: low — 1 source]

- Single WebSocket connection to Chrome via the Chrome DevTools Protocol (CDP) — no intermediate abstraction layer between agent and browser.
- Self-healing: when a helper is missing, the agent writes it into `agent_helpers.py` at execution time, so the harness grows its own capabilities.
- Domain skills system: reusable, site-specific skill files (selectors, flows, edge cases) stored in `agent-workspace/domain-skills/` and generated by the agent, not hand-authored.
- Skill registration via `browser-harness skill` command; setup prompt designed to be pasted into a coding agent (Claude Code, Codex) for zero-friction onboarding.
- Supports both local Chrome (via `--remote-debugging-port`) and Browser Use Cloud browsers for isolated/headless/stealth deployments.

## Key Features [coverage: low — 1 source]

- Direct CDP connection to any running Chrome/Chromium instance — no driver, no Selenium/Playwright abstraction overhead.
- Runtime agent self-modification: agent writes helpers into its own workspace when it encounters missing functionality.
- Domain skills library with examples for GitHub, LinkedIn, Amazon, and more; contributed via PR.
- Browser Use Cloud integration: free tier with 3 concurrent browsers, proxies, and captcha solving; no card required.
- Minimal codebase (~1k lines across 4 core files) designed to be readable and editable.
- Environment variable `BH_DOMAIN_SKILLS=1` to enable domain skills from the agent workspace.
- Supports sub-agents and headless/stealth browser modes via cloud tier.

## Use Cases [coverage: low — 1 source]

- Browser automation tasks requiring full, unconstrained access to the DOM and browser internals.
- Agentic workflows where an LLM must complete multi-step web tasks (file uploads, form submissions, scraping).
- Site-specific automation at scale: LinkedIn outreach, Amazon ordering, expense filing.
- Headless/stealth browser deployments via Browser Use Cloud.
- Coding agent assistants (Claude Code, Codex) that need browser control as a tool.
- Persistent browser sessions across agent runs with accumulated domain knowledge.
